# ЭЛЕМЕНТАРНО

Вдумчивое разглядывание. Приложение получает фотографию (или серию кадров)
сцены и восстанавливает **что здесь происходило и кто здесь был** — по прямым
и, главное, по косвенным признакам: следы присутствия, следы привычек,
несоответствия физике, отсутствие того, что должно было быть.

«Шерлок» здесь — не про преступления, а про принцип: внимательно смотреть,
сопоставлять мелочи, идти от общего к частному. Роджённые из этого правила
задачи («кто это сделал?», «что изменилось между кадрами?») — развлекательный
слой поверх той же машины.

Выводы о людях ограничены тремя уровнями: **присутствие**, **действие**,
**роль или привычка**. Вина, намерение и черты характера из фотографии не
выводятся — это не абдукция, и протокол такому выводу отказывает.

Ключевое отличие от «ещё одного промпта для VLM»: приложение **не сочиняет
историю, а предъявляет доказательства**. Каждое утверждение связано с регионом
изображения, идентификатором правила из версионированной базы и источником.
Если улик недостаточно — приложение отказывается отвечать.

## Лестница вывода

Ответ строится ступенями, и каждая опирается на свои улики:

```
сцена  →  активность  →  присутствие  →  действие
```

«Место: рабочий кабинет» → «Чем здесь занимались: переставляли вещи» →
«Кто был в сцене: садовник» → «Что именно делали: вошёл с улицы, оставив
грязный след». Перепрыгнуть ступень нельзя: ступень без своих улик не
появляется в ответе.


## Что уже есть на рынке (проверено при первичной проработке)

| Продукт | Что делает | Чего не делает |
| --- | --- | --- |
| **Probe** (iOS/Android/web) | Реконструкция сцены: аннотированные маркеры улик, confidence-скоры, таймлайн, «next steps», OSINT по EXIF, экспорт отчёта | Ссылки на правила и источники; измеримая калибровка; опровержимость; отрицательные улики как first-class |
| **RoomDetective** | Фото комнаты → «одна улика, которую вы перестали замечать» + «один ход, который изменит дело»; эвристики + база знаний по экологической психологии | Проверяемость эвристик, версионирование базы, отказ отвечать |
| **Sherlock** (датасет, Hessel et al., ECCV 2022) | 103K фото, 363K пар «улика → вывод», bbox-разметка улик, человеческие оценки правдоподобия | Это данные, а не продукт; сайт проекта долго был в статусе «Coming Soon» |

Академия подтверждает и задачу, и разрыв: **NL-Eye** (2024) — VLM в визуальной
абдукции работают на уровне случайного угадывания при сильном человеческом
результате; **AbductiveMLLM** (AAAI 2026, Oral) — текущий SOTA; **Absence is
Presence** (2026) фиксирует *affirmation bias* моделей: они не замечают того, чего
**нет**, — а именно отсутствие и есть самые «шерлоковские» улики.

Вывод: **уникальность — не в восприятии и не в прозе, а в протоколе.** Восприятие
и стиль можно повторить за вечер. Версионированная база правил с источниками,
конфаундами и тестами — нет.

## Принципы

1. **Ссылка обязательна.** Утверждение без `finding_id` — ошибка валидатора, а не
   предупреждение. Валидация живёт в коде, а не в промпте.
2. **Правило — это цитируемый артефакт.** У каждого: идентификатор, версия,
   сигнатура, вывод, конфаунды, исключения, условие опровержения, источник.
   Черновик правила не может обосновать сильное утверждение.
3. **Калибровка измеряется, а не декларируется.** Утверждение не может превышать
   потолок уверенности, заданный правилом.
4. **Отрицательные улики — первоклассные.** Пылевой контур, пустой крюк,
   невыцветший прямоугольник — такие улики требуют отдельной поддержки в
   восприятии, потому что модели склонны описывать только присутствующее.
5. **Отказ — корректный ответ.** «Улик недостаточно» — валидный исход, а не
   провал.
6. **Интерпретация отделена от факта.** Семиотика и «глубокие слои смысла»
   помечены как спекулятивные и не смешиваются с проверяемыми выводами.
7. **О людях — только о присутствии, действии и роли.** Вина, намерение и
   черты характера из фотографии не выводятся. Обвинительные формулировки
   отклоняются валидатором, а не просьбой к модели.
8. **Человеку — не только про преступления.** Любая сцена: рабочий кабинет,
   кухня, мастерская, дача. Криминальный сюжет — частный случай, а не рамка
   продукта.

## Быстрый старт

### Как пользоваться из opencode

Новая сессия не нужна: скилл `detective` установлен глобально
(`~/.config/opencode/skills/detective/`) и доступен в любом каталоге.

```bash
# положить фото в файл и разобрать его — обычным сообщением:
#   «проанализируй ~/Downloads/photo.jpg по протоколу ЭЛЕМЕНТАРНО»
# или командой (работает отовсюду после установки):
/detective ~/Downloads/photo.jpg
```

Агент сам подхватит скилл, пройдёт девять фаз и вернёт ответ с уликами
`[RULE-ID]`, оговорками, попыткой опровержения, версиями и следующим
вопросом. Серия кадров — укажи каталог или несколько файлов.

Файл лучше, чем вложение: агент читает изображение с диска, а канал
вложений умеет не доставить картинку модели.

Если скилл в репозитории изменён, глобальная копия устареет и правка не
даст эффекта. Это проверяется тестом; переустановить:

```bash
python3 tools/install_skill.py          # установить или обновить
python3 tools/install_skill.py --check  # только проверить
```

### Как пользоваться из командной строки

```bash
# полный разбор одной фотографии: восприятие → улики → версия
python3 -m tools.elementarno.cli analyze photo.jpg --persona doyle

# только сцена-граф (посмотреть, что извлечено)
python3 -m tools.elementarno.cli perceive photo.jpg --out /tmp/scene.json --raw /tmp/raw.json

# улики с цитатами и источниками
python3 -m tools.elementarno.cli findings /tmp/scene.json

# что изменилось между двумя кадрами
python3 -m tools.elementarno.cli diff before.json after.json --json

# загадка по серии кадров
python3 -m tools.elementarno.cli puzzle puzzle.json --persona doyle

# слой рассуждения: связать улики в утверждения и версии (модель формулирует, протокол отсекает)
python3 -m tools.elementarno.cli reason scene.json --persona doyle --out ledger.json

# что снять дальше: вопросы ранжированы по ценности информации
python3 -m tools.elementarno.cli nextshot scene.json

# серия фото: накопление улик и уточняющие вопросы между кадрами
python3 -m tools.elementarno.cli session --image a.jpg --image b.jpg --state case.json

# проверка утверждений: ссылки, потолки, фальсифицируемость
python3 -m tools.elementarno.cli verify scene.json --ledger ledger.json

# доска разбора: одна HTML-страница с уликами, нитями между ними и переразбором
python3 -m tools.elementarno.cli board scene.json --ledger ledger.json --out board.html

# тесты и бенчмарки
python3 -m unittest discover -s tests -t .
python3 tools/run_eval.py

# харнесс над скиллом: кейс → агент → артефакты → скорер
python3 tools/run_skill.py

# измерение на реальных фотографиях (с повторами: ответы модели стохастичны)
nix develop --command python3 tools/run_real.py --repeat 3
```

Путь через агента и путь через движок — не одно и то же. Агент смотрит сам
и умеет кропы, поэтому находит больше: на `mold-wall` человек-агент нашёл
плесень там, где движковое восприятие её не нашло. Движок нужен там, где
требуется воспроизводимость и измерение.

Окружение с зависимостями (Pillow нужен для кроп-допроса):

```bash
nix develop            # python3 + pillow + numpy + ruff + jq
nix flake check       # тесты в изолированном окружении
```

Зависимостей у самого движка нет — только стандартная библиотека Python 3.11+.

## Доска разбора

`board` собирает разбор в одну HTML-страницу: доска с карточками и нитями
(след → улика → утверждение → версия), таблица всех находок с оговорками,
источниками и опровержениями, карточки утверждений с исходом отрицания и
версии с различающими вопросами.

```bash
python3 -m tools.elementarno.cli board scene.json --ledger ledger.json --out board.html
```

Страница самодостаточна: один файл, без сети и без зависимостей. Клик по
карточке оставляет только связанные нити, вкладка «Переразбор» отдаёт леджер
для правки и команды перезапуска движка.

Правка текста на странице ничего не меняет в разборе: истину считает движок.
Доска показывает разбор и собирает команду, а не заменяет протокол.

Образец: `docs/board-sample.html` (синтетический кейс бенчмарка).

## Восприятие: три прохода

1. **Инвентаризация** — что есть: объекты, поверхности, свет. Регионов здесь
   нет намеренно.
2. **Чек-лист** — 25 бинарных вопросов по типам следов: «брызги краски — да
   или нет?». Классификацию выполняет не модель, а сама таблица вопросов.
3. **Проверка** — подтверждение находки по её собственному описанию.

Почему именно так: если просить модель раскладывать видимое по нашей
таксономии, она подгоняет («брызги краски» → «stain», «следы ног» →
«disturbed_dust») и выдумывает отсутствие там, где его нет. Измерение на 12
реальных фотографиях это показало прямо: recall вырос с 0.125 до 0.667, а
находки на чистых кухнях упали с 3 до 2 — и обе оставшиеся оказались
настоящими следами (кольцо от кружки, отпечаток на стекле), а не выдумкой.

Сырые ответы модели сохраняются рядом со сценой — они часть цепочки
доказательств. Измеренная задержка на кадр: 12–20 с, 2–4 вызова модели.
