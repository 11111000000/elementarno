# Кейсы для харнесса скилла

Здесь лежат кейсы, по которым `tools/run_skill.py` гоняет скилл
`detective`. Кейс — это одна фотография, набор доменных паков и ожидания:
какие улики должны сработать и каким должен быть вердикт.

## Формат

```json
{
  "cases": [
    {
      "id": "mold-wall",
      "image": "eval/real/images/mold-wall.jpg",
      "packs": ["core", "absence", "biology", "water"],
      "expect": {
        "finding_ids": ["F-BIO-002"],
        "verdict": "sufficient_evidence"
      },
      "note": "что этот кейс меряет"
    }
  ]
}
```

| поле | что значит |
| --- | --- |
| `id` | идентификатор кейса; им же называется каталог артефактов |
| `image` | путь к снимку относительно корня репозитория |
| `packs` | доменные паки, по которым считаются улики; пустой список — все правила |
| `expect.finding_ids` | `finding_id`, которые должны сработать; лишние считаются отдельно |
| `expect.verdict` | `sufficient_evidence`, `insufficient_evidence` или `conflicting_evidence` |
| `note` | что кейс меряет и на что смотреть при разборе промаха |

Истина берётся из категории файла на Wikimedia Commons, а не из вывода
модели: иначе харнесс измерял бы согласие модели с самой собой.

## Прогон

```bash
python3 tools/run_skill.py --offline          # план прогона, без модели
python3 tools/run_skill.py                    # полный прогон
python3 tools/run_skill.py --limit 1 --repeat 3
python3 tools/run_skill.py --persona forensic --json
```

Коды выхода: `0` — всё прошло, `1` — нашлись нарушения протокола, `2` —
ошибка настройки (нет ключа MiniMax, битый манифест), `3` — кейс не
отработал (сеть или ответ модели без JSON).

Артефакты каждого прогона: `eval/skill-runs/<id>/` — `scene.json`,
`findings.json`, `ledger.json`, `answer.txt`, `raw.json`. Сводка по всем
кейсам — `eval/skill-runs/summary.json`.

## Что считает харнесс

| метрика | что значит | чего ждём |
| --- | --- | --- |
| `protocol_violations` | ошибки `elementarno.ledger.validate` на леджере агента | ноль всегда |
| `citation_completeness` | доля утверждений с разрешающимися ссылками | 1.0 |
| `finding_recall` | доля ожидаемых улик, которые сработали | растёт |
| `extra_findings` | улики сверх ожиданий | ноль на чистых кадрах |
| `refutation_coverage` | доля утверждений с непустым `refutation` | 1.0 |
| `discriminator_coverage` | доля версий с непустым `discriminator` | 1.0 |
| `claims_without_refutation` | сколько утверждений осталось без отрицания | ноль |
| `hypotheses_without_discriminator` | сколько версий осталось без дискриминатора | ноль |
| `refusal_accuracy` | доля кейсов, где вердикт совпал с ожиданием | ≥ 0.85 |
| `latency_s`, `calls` | время прогона и число вызовов модели | для сравнения витков |

`claims_without_refutation` и `hypotheses_without_discriminator` — прямые
счётчики двух требований протокола, которых раньше не измеряли: отрицание
обязательно для утверждения, идущего дальше вывода улики, а дискриминатор
обязателен у каждой версии.

Оговорка к `refutation_coverage`: утверждение, которое дословно повторяет
вывод своей улики, отрицать не нужно — работает опровержение самого правила.
Такое утверждение валидатор прощает, а счётчик покрытия считает его
непокрытым. Поэтому смотреть надо на оба числа вместе: `refutation_coverage`
показывает форму леджера, `protocol_violations` — настоящие нарушения.

## Как добавить кейс

1. Положить снимок в `eval/real/images/` (или указать путь к любому
   изображению в репозитории).
2. Написать, что на снимке и почему верна именно такая улика.
3. Взять `finding_id` из `rules/*.json`: `F-<ID правила>`.
4. Добавить кейс в `cases.json` и проверить манифест:
   `python3 tools/run_skill.py --offline`.

## Чего этот харнесс не измеряет

- **Восприятие агента.** Фазы 1–2 берут сцена-граф у движка
  (`MiniMaxPerception.scene_graph`), а не у агента, который читает кадр сам.
  На кейсе `mold-wall` человек-агент плесень находит, а движковое
  восприятие — нет; харнесс покажет расхождение, но не сможет его закрыть.
- **Диалог.** Фаза 7 задаёт вопрос, но ответ пользователя в прогон не
  приходит: один проход на кейс, без уточнений.
- **Кропы и второй взгляд.** Агент в opencode умеет снять кроп и
  пересмотреть кадр; здесь модель видит исходный снимок целиком.
