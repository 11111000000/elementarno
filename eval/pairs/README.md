# Пары «до/после» для правил отсутствия

Отдельный бенчмарк: не «что на картинке», а **«сработает ли правило там, где
след есть, и не сработает ли там, где следа нет»**. Закрывает пробел, который
не закрывается остальным бенчмарком: на `eval/benchmarks/` нет ни одной сцены с
отрицательными уликами, поэтому метрика «ложных срабатываний» до сих пор
измерялась на кадрах, где ложное срабатывание невозможно.

---

## ⚠️ Сейчас здесь только синтетические пары

Все пары в `manifest.json` **нарисованы генератором**, фотографий нет.
Значит:

- метрика «ложных срабатываний» на этом наборе измеряет **работу движка**
  (срабатывает ли правило там, где в сцене стоит аннотация следа), а **не
  мир**: настоящий пылевой контур на фотографии выглядит иначе, чем
  нарисованный прямоугольник, и модель может его не увидеть;
- цифры этого бенчмарка **нельзя** переносить на реальные фотографии и нельзя
  сравнивать с порогом `FP rate ≤ 0.02` из `docs/QUALITY-LOOP.md`;
- **настоящие пары — следующий шаг.** Инструментарий к ним готов: методика
  съёмки — `docs/CAPTURE-PROTOCOL.md`, формат манифеста тот же, скорер тот
  же, различать реальные и синтетические пары он умеет по полям `real` и
  `synthetic`.

---

## Устройство

```
eval/pairs/
  manifest.json                 список пар: кадры, ожидаемые правила, истина
  README.md                     этот файл
  synthetic/<id>/
    before.json  after.json  clean.json    сцены-графы
    before.png   after.png   clean.png      что это за пара, глазами
  real/<id>/                    будущие настоящие пары: фото + сцены + сырые ответы
```

Три кадра одной пары:

| Кадр | Содержимое | Ожидание |
| --- | --- | --- |
| `before` | предмет на месте, отрицательная улика видна | правило **сработало** |
| `after` | предмет убран, след не читается | правило **не сработало** |
| `clean` | контроль: предмет здесь никогда не стоял | правило **не сработало** |

Поле `expect.trace_frame` говорит, в каком кадре читается улика. У синтетики
это `before`; у настоящих пар чаще `after`: пылевой контур под снятым
предметом становится виден после того, как предмет убрали.

Переход «до → после» в синтетике означает **исчезновение** улики: так
проверяется чувствительность движка к наличию аннотации следа. Физика
настоящего пылевого контура обратная — после снятия предмета он становится
заметнее, а не пропадает. Настоящие пары это учитывают: кадр с уликой у них
обычно «после», и это записано в `expect.trace_frame`.

## Формат манифеста

```json
{
  "note": "…",
  "pairs": [
    {
      "id": "syn-dust-outline-shelf",
      "before": "synthetic/syn-dust-outline-shelf/before.json",
      "after": "synthetic/syn-dust-outline-shelf/after.json",
      "clean": "synthetic/syn-dust-outline-shelf/clean.json",
      "expect": {"finding_ids": ["F-ABS-001"], "trace_frame": "before"},
      "truth": "С полки сняли керамическую вазу…",
      "real": false,
      "synthetic": true
    }
  ]
}
```

Пути относительно `eval/pairs/`. Для настоящих пар добавляются `photos`
(файлы фотографий) и `quality` (`good` / `rejected`); формат описан в
`docs/CAPTURE-PROTOCOL.md` §6.

## Команды

```bash
python3 tools/make_pairs.py          # пересобрать синтетические пары и манифест
python3 tools/score_pairs.py         # сводка по парам, ненулевой код при провале
python3 tools/score_pairs.py --json  # тот же отчёт в JSON
python3 tools/score_pairs.py --out /tmp/pairs.json
```

Генератор детерминирован: перезапуск не меняет файлы и не добавляет времени
в содержимое.

## Что считает скорер

| Метрика | Смысл | Провал |
| --- | --- | --- |
| `negative_detected` | правило сработало на кадре с уликой и **не** сработало на втором кадре | улика пропущена или «залипла» на обоих кадрах |
| `false_positive` | правило сработало на контрольной «чистой» сцене | движок выдумывает отсутствие |
| `consistency` | наборы сработавших правил «после» и «чистой» совпали | уборка предмета оставила лишние улики |

`false_positive` считается по пакету проверяемых правил (`absence`): если на
чистой сцене сработало правило из другого пака, оно попадает в
`clean_extra` и не портит метрику, но попадает в отчёт.

Пара проходит, если все три условия выполнены. Любая непрошедшая пара
даёт ненулевой код возврата.

## Что здесь проверяется, а что — нет

**Проверяется:** правило отсутствия реагирует на наличие улики, не реагирует
на её отсутствие и не оставляет следов на пустой сцене.

**Не проверяется:** качество восприятия модели (оно меряется на
`eval/real/` через `tools/run_real.py`), вероятность в мире, порог
`FP rate ≤ 0.02` — на синтетике его подтвердить нельзя в принципе.

## Как добавить настоящую пару

1. Снять по `docs/CAPTURE-PROTOCOL.md` (12 пар — минимум, 20 — цель).
2. Получить сцены-графы: `python3 -m tools.elementarno.cli perceive photo.jpg --out scene.json --raw raw.json`.
3. Поправить сцены руками (подтвердить или убрать регионы).
4. Дописать запись в `manifest.json` с `"real": true, "synthetic": false`.
5. Прогнать `python3 tools/score_pairs.py` и посмотреть, что сломалось.
