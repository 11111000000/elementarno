# Архитектура

Слои снизу вверх. Каждый верхний слой **не может** добавить факт, которого нет
в нижнем. Это и есть защита от галлюцинаций: не промпт, а запрет в коде.

```
┌─────────────────────────────────────────────────────────┐
│  L5  Персона / подача        Doyle · Conan Doyle · …    │  тон, риторика
├─────────────────────────────────────────────────────────┤
│  L4  Режимы                  detective · audit · solve   │  что именно делаем
│                              nextshot · forensic         │
├─────────────────────────────────────────────────────────┤
│  L3  Гипотезы                набор версий, log-odds,     │  конкурирующие
│                              kill-log, карточки          │  объяснения
│                              фальсификации               │
├─────────────────────────────────────────────────────────┤
│  L2  Правила (паки)          версионированные, с         │  «что на что
│                              источниками и конфаундами    │  указывает»
├─────────────────────────────────────────────────────────┤
│  L1  Сцена-граф              объекты, поверхности,       │  что видно
│                              регионы, наблюдения         │
├─────────────────────────────────────────────────────────┤
│  L0  Восприятие              детектор → регионы → признаки│  пиксели
└─────────────────────────────────────────────────────────┘
```

## L0 → L1: восприятие

Восприятие вне ядра: детектор (OWLv2 / Grounding DINO) → маски (SAM2) → геометрия
(Depth Anything) → признаки по кропам (VLM спрашивают **регион**, а не всю
картинку: кроп-уровневый вопрос даёт заметно более точный ответ). На выходе —
сцена-граф по `schemas/scene-graph.schema.json`.

Признаки, которых нет в графе, не считаются уликами. Модель не может «увидеть»
то, чего нет в графе.

## L2: доменные паки правил

Широкий спектр применения реализуется **паками**, а не одной базой:

| Пак | Что покрывает | Примеры правил |
| --- | --- | --- |
| `core` | универсальные проверки для любой сцены | тень не совпадает с источником света; гравитация; уровень жидкости; след от предмета |
| `absence` | улики отсутствия | пылевой контур; пустой крюк; невыцветший прямоугольник; один комплект посуды при двух стульях |
| `water` | залив, протечка, влага | разводы от высохшей воды; направление потока; плесень после заливки |
| `fire` | пожар, горение | V-образование на полу; сплавление металла; глубина обугливания |
| `mechanics` | поломки, ДТП, износ | след торможения; деформация по направлению удара; несовпадение следов шин |
| `biology` | следы жизни, вредители | следы грызунов; период заселения; плесень как индикатор влажности |
| `semiotics` | символы, артефакты, культура | опознаваемый логотип; книга на полке; флаг; символика |

Пак — это просто набор правил с полем `domain`. Подключение нового домена не
требует правок движка: новый файл `rules/<pack>.json` + строка в реестре.
Тематический пак работает на любой сцене, но его правила требуют соответствующей
области наблюдения — поэтому у каждого правила есть `requires` (какие поля графа
обязаны присутствовать, иначе правило молча не срабатывает).

**Ядро + пак** — это и есть «широкий спектр»: движок один, домен подключается
декларативно.

## L3: гипотезы

Гипотеза — конкурирующее объяснение, а не единственная история. Ведётся
набор версий:

- вес (`log_odds`) пересчитывается при добавлении улики;
- `kill_log` хранит, **какая именно улика** убила версию — это и есть
  человекочитаемая логика Шерлока;
- карточка фальсификации: «что опровергло бы эту версию» и «как это проверить
  физически»;
- версии не вытесняют друг друга: по умолчанию показываются все живые, а не
  только победитель.

## L4: режимы

| Режим | Вопрос пользователя | Что делает | Гарантия |
| --- | --- | --- | --- |
| `detective` | «Что здесь произошло?» | строит версии и рассказывает | каждая фраза привязана к улике; есть отказ |
| `audit` | «Проверь, что видно на фото» | только наблюдения, без интерпретаций | нет гипотез, нет шуток, нет персонажа |
| `forensic` | «Что произошло в этом доме?» | пак домена + строгий отчёт с источниками | цитаты обязательны |
| `solve` | «Как мне это починить / как избежать» | контрфактические правки сцены и следствия | каждое действие — с оценкой риска и цены |
| `nextshot` | «Что ещё снять, чтобы разобраться?» | максимизация различения версий | выбор кадра обоснован, а не общий совет |

Режимы различаются не только текстом, но и **порогами**: в `audit` любая
непроверяемая реплика — ошибка, в `detective` допустима стилизация.

## L5: персона

Персона — **рендерер над проверенным леджером**, а не генератор текста.

Правила персон:

1. Рендерер получает только валидированные утверждения. Попытка отрендерить
   невалидированное — исключение, а не предупреждение.
2. Персона **не может** изменить `confidence`, добавить улику или смягчить
   отказ.
3. Каждая фраза сохраняет цитату `[RULE-ID]`.
4. Выход персона помечен как повествование (футер-дисклеймер), чтобы
   читатель не принял стиль за достоверность.
5. Персона выбирается из реестра и может быть расширена без правок движка:
   это шаблоны подстановки, а не free-form генерация.

Режим `audit` персон не допускает вовсе — это его отличие от `detective`.

Персона «в стиле Конан Дойла» — ироничная, а не пародийная: она не придумывает
улики, она их предъявляет. Если улик нет, она так и говорит.

## Конфигурация

Приложение конфигурируемо: профиль задаёт паки, режим, персону, пороги и
запреты.

```json
{
  "id": "household-incident",
  "title": "Бытовой инцидент",
  "packs": ["core", "absence", "water", "biology"],
  "mode": "forensic",
  "persona": null,
  "min_findings": 2,
  "allow_interpretation": false
}
```

Профили лежат в `config/profiles.json`, выбираются флагом `--profile`.
Это позволяет выпустить один движок с разными «лицами»: страховой эксперт,
риелтор, следователь, «сервис проверки объявления».

## Конфиденциальность

Локальный режим: детектор и мелкая VLM на устройстве, наружу уходит только
текст утверждений. Для сцен частных квартир это снимает главный барьер.
