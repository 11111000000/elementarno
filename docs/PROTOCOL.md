# Протокол доказательности

Контракт, который отличает ЭЛЕМЕНТАРНО от «промпта с красивым текстом».
Нарушение протокола — это баг, а не стилистическое предпочтение.

## 1. Доказательный контракт

Каждое утверждение (**claim**) обязано:

1. ссылаться хотя бы на одну **улику** (`finding_id`);
2. иметь `confidence`, не превышающий потолок, заданный правилами-основаниями;
3. если основание — черновик правила, иметь `confidence ≤ 0.5` и `provisional: true`;
4. если это гипотеза — иметь условие опровержения;
5. если это интерпретация — иметь `speculative: true` и `confidence ≤ 0.4`.

Улика (**finding**) обязана ссылаться на:

- правило (`rule_id` + `rule_version`), у которого в свою очередь есть
  непустые `sources` и непустые `confounds`;
- якоря в сцене (`anchors`) — идентификаторы регионов/объектов, на которые
  улика опирается.

Ничего из этого не проверяется моделью: проверка в коде
(`tools/elementarno/ledger.py`), потому что модель, которая сама себя
проверяет, склонна подтверждать саму себя.

## 2. Сцена-граф

`schemas/scene-graph.schema.json`. Коллекции:

- `surfaces` — поверхности (стол, пол, стена): материал, пыль, влажность, площадь;
- `objects` — объекты: категория, материал, состояние, заполненность, положение, на чём стоит;
- `regions` — локальные участки: `kind` (пылевой контур, трещина, потёртость, след), форма, площадь, контраст, свежесть, bbox;
- `observations` — признаки, снятые с конкретного региона: `about` → `region`, `feature`, `value`, `confidence`;
- `metadata` — EXIF и прочее.

Поля, которых нет в графе, не могут быть основанием для вывода. Это
сознательное ограничение: лучше «не знаю», чем правдоподобная выдумка.

## 3. DSL предикатов

Минимальный, проверяемый, без eval-строк. Условие — один из видов:

| Вид | Смысл | Пример |
| --- | --- | --- |
| `present` | по пути есть значение, равное указанному | `{"kind":"present","path":"surfaces[name=table].dust_present","value":true}` |
| `count` | количество элементов по пути в границах | `{"kind":"count","path":"regions[kind=dust_outline]","gte":1,"lte":10}` |
| `absent` | по пути ничего нет | `{"kind":"absent","path":"objects[category=laptop]"}` |
| `not` | отрицание условия | `{"kind":"not","condition":{...}}` |
| `all` / `any` | комбинация | `{"kind":"all","conditions":[...]}` |
| `rule` | другое правило сработало | `{"kind":"rule","id":"PHYS-001"}` |

Путь: `коллекция[фильтр=значение][фильтр=значение].поле`.

- `regions[kind=dust_outline]` — все регионы этого вида;
- `surfaces[name=table].dust_present` — поле `dust_present` у поверхности с именем `table`;
- `objects[category=mug].fill_level` — список значений.

Сравнение строк — регистронезависимое. Числа сравниваются численно.

## 4. Улика

```json
{
  "finding_id": "F-ABS-001",
  "rule_id": "ABS-001",
  "rule_version": 1,
  "pack": "absence",
  "title": "Пылевой контур от недавно убранного предмета",
  "inference": "...",
  "anchors": ["r1"],
  "sources": [{"ref": "...", "note": "..."}],
  "confidence_prior": 0.65,
  "confidence_ceiling": 0.85,
  "provisional": true
}
```

`confidence_prior` — априорная вероятность того, что объяснение верно при
сработавшем предикате. `confidence_ceiling` — потолок, выше которого утверждение
не может подняться **никогда**: известные исключения правила не исчезают от
того, что модель уверенно себя чувствует.

`provisional: true` — улика от черновика правила. Черновик не может обосновать
сильное утверждение.

## 5. Утверждение

```json
{
  "claim_id": "C-1",
  "kind": "observation",
  "text": "На столе виден прямоугольный контур без предмета",
  "support": [{"finding_id": "F-ABS-001"}],
  "confidence": 0.6,
  "provisional": true,
  "confounds": ["..."],
  "falsification": "...",
  "interpretation": false
}
```

`kind`:

- `observation` — что видно; твёрдая опора на графе;
- `inference` — что из этого следует по правилу;
- `hypothesis` — конкурирующее объяснение целого;
- `interpretation` — смысловая, семиотическая догадка: всегда `speculative`.

## 6. Гипотезы и kill-log

```json
{
  "hypothesis_id": "H-1",
  "text": "Кто-то недавно убрал предмет со стола",
  "claims": ["C-1", "C-2"],
  "status": "open",
  "log_odds": 1.2,
  "kill_log": [{"rule_id": "PHYS-002", "note": "тень не совпадает с источником света"}]
}
```

`log_odds` — грубая байесовская аппроксимация: сумма логитов априорных
вероятностей улик-оснований минус штраф за конфаунды. Это не точная
статистика, а **упорядоченное сравнение**: версии ранжируются, а не «доказываются».

`status: "rejected"` допустимо только при непустом `kill_log`. Убитая версия
остаётся в леджере — видно, что её исключили и чем.

## 7. Политика отказа

Режим требует минимум улик (`min_findings` в профиле). Если улик меньше,
движок возвращает `verdict: "insufficient_evidence"`, а не «всё нормально».

Отказ — это результат, а не ошибка. В режиме `detective` отказ отдаётся в той же
персоне, что и остальной текст.

## 8. Правило

```json
{
  "id": "ABS-001",
  "version": 1,
  "pack": "absence",
  "title": "...",
  "domain": "absence",
  "requires": ["surfaces", "regions"],
  "depends_on": [],
  "predicate": {"kind": "all", "conditions": [...]},
  "inference": {
    "claim": "...",
    "confidence_prior": 0.65,
    "confidence_ceiling": 0.85
  },
  "anchors": ["regions[kind=dust_outline].id"],
  "confounds": ["..."],
  "exceptions": ["..."],
  "falsification": {
    "refuted_by": ["ABS-002"],
    "physical_test": "..."
  },
  "sources": [{"ref": "...", "note": "...", "verified": false}],
  "review_status": "draft"
}
```

Обязательные поля: `id`, `version`, `title`, `domain`, `predicate`, `inference`,
`confounds` (непустой), `exceptions`, `falsification`, `sources` (непустой),
`review_status`.

`review_status`:

- `draft` — написано, не проверено экспертом → улика `provisional`;
- `reviewed` — проверено → улика может обосновать сильное утверждение.

`sources[].verified: false` — источник не открывался и не сверялся. Правило с
непроверенным источником **не может** переводить утверждение выше `0.5`.

## 9. Изменение смысла правила

Смысл правила изменился → бамп `version` → запись в `rules/CHANGELOG.md`.
Наборы улик версионируются вместе с правилами: у находа хранится
`rule_version`, поэтому старый отчёт нельзя переиначить новым правилом молча.

## 10. Метрики

- **Grounding precision** — доля утверждений, у которых все якоря реально
  присутствуют в графе. Цель: ≥ 0.9.
- **Citation completeness** — доля утверждений с разрешающимися ссылками. Цель: 1.0.
- **Calibration (Brier / ECE)** — соответствие заявленной уверенности реальной
  частоте. Цель: ECE ≤ 0.15 на размеченном наборе.
- **Refusal accuracy** — доля случаев, где отказ был правильным. Цель: ≥ 0.85.
- **Hypothesis ranking (top-k)** — доля случаев, где истинная версия в топ-k.
  Цель: top-3 ≥ 0.8.
